### 🔍 Data Verification Queries

Use these SQL queries to verify scraper results:

#### Check Modifier Data for a Restaurant

```sql
-- Check modifier groups
SELECT mg.id, mg.name, COUNT(DISTINCT dm.id) as modifier_count
FROM menuca_v3.modifier_groups mg
LEFT JOIN menuca_v3.dish_modifiers dm ON dm.modifier_group_id = mg.id
WHERE mg.restaurant_id = <V3_RESTAURANT_ID>
GROUP BY mg.id, mg.name
ORDER BY mg.name;

-- Check dish modifiers
SELECT d.name as dish_name, 
       mg.name as modifier_group, 
       dm.name as modifier_name,
       COUNT(dmp.id) as price_count
FROM menuca_v3.dishes d
JOIN menuca_v3.dish_modifiers dm ON dm.dish_id = d.id
JOIN menuca_v3.modifier_groups mg ON mg.id = dm.modifier_group_id
LEFT JOIN menuca_v3.dish_modifier_prices dmp ON dmp.dish_modifier_id = dm.id
WHERE d.restaurant_id = <V3_RESTAURANT_ID>
GROUP BY d.name, mg.name, dm.name
ORDER BY d.name, mg.name, dm.name;
```

#### Check for Orphan Data

```sql
-- Orphan modifiers (no valid dish)
SELECT dm.id, dm.name
FROM menuca_v3.dish_modifiers dm
LEFT JOIN menuca_v3.dishes d ON d.id = dm.dish_id
WHERE d.id IS NULL;

-- Orphan modifier prices (no valid modifier)
SELECT dmp.id, dmp.price
FROM menuca_v3.dish_modifier_prices dmp
LEFT JOIN menuca_v3.dish_modifiers dm ON dm.id = dmp.dish_modifier_id
WHERE dm.id IS NULL;
```

### 🚨 Common Pitfalls & How to Avoid

#### Pitfall 1: ID Confusion
**Problem:** Using V1 IDs for database operations or V3 IDs for CRM scraping  
**Solution:** Always check `v1_v3_id_mapping.csv` before any ID usage  
**Example:** Restaurant 147 in DB ≠ Restaurant 147 in CRM

#### Pitfall 2: Duplicate Data
**Problem:** Running scraper multiple times creates duplicate modifiers  
**Solution:** Check if data exists before inserting (use UPSERT or SELECT first)  
**Query:**
```sql
SELECT id FROM menuca_v3.modifier_groups 
WHERE restaurant_id = ? AND name = ?;
```

#### Pitfall 3: Missing Prerequisites
**Problem:** Trying to add modifiers for dishes that don't exist  
**Solution:** Always verify dish exists before creating modifiers  
**Use:** `v3_id NOT IN (607, 924, 948, 949)` filter for Phase 1

#### Pitfall 4: Wrong Restaurant Count
**Problem:** Documentation mentions 173 or other numbers  
**Solution:** The CORRECT count is 166 V1 restaurants (verified multiple times)  
**Breakdown:** 166 V1 + 24 V2 = 190 total active restaurants

#### Pitfall 5: Scraping Inactive Restaurants
**Problem:** CRM contains ~240 restaurants, but only 166 are active V1  
**Solution:** ONLY scrape restaurants in `v1_v3_id_mapping.csv` (166 entries)  
**Do NOT:** Scrape all restaurants from CRM
